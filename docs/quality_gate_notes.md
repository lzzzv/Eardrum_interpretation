# 影像防呆（Quality Gate）測試記錄 — 2026-08-10

## 目前門檻值（v1，暫定，非最終標準）

定義於 `ImageQualityChecker.kt`：

| 檢查項目 | 門檻 | 說明 |
|---|---|---|
| 太暗 | 平均亮度 < 60 | 灰階 0-255 |
| 太亮 | 平均亮度 > 200 | 灰階 0-255 |
| 太模糊 | Laplacian 變異數 < 45 | 200px 分析尺寸下計算 |
| 不像耳鏡照片 | 四角平均亮度 ≥ 40，或「中心-四角」亮度差 ≤ 50 | 判定為缺少耳鏡黑色暈影特徵 |

這些數字是根據下方測試資料校準的**起始值**，樣本數還很小（9 張真實照片 + 合成邊界圖），
**未來拿到更多實際使用者上傳的照片後，務必重新統計分布再調整**，不要當成固定標準。

  「騙過耳鏡形狀偵測」的圖（黑邊+灰白圓盤、暗畫面+右上角亮斑）

## 測試結果摘要

**真實照片放行率：9 / 9**（全部正確通過品質檢查，沒有誤擋）

**邊界圖片攔截率：11 / 12**

| 檔名 | 結果 | 原因 |
|---|---|---|
| pure_black / pure_white | 擋下 | 太暗 / 太亮 |
| near_black_noise / near_white_noise | 擋下 | 太暗+太模糊 / 太亮+太模糊 |
| random_noise | 擋下 | 不像耳鏡照片（四角=中心，無暈影） |
| gradient_sky | 擋下 | 太模糊 + 不像耳鏡照片 |
| scene_landscape | 擋下 | 不像耳鏡照片（四角太亮，無黑色暈影） |
| blurred_real_normal / blurred_real_abnormal | 擋下 | 太模糊（對真實照片套模糊處理後仍正確攔截） |
| dark_real_normal | 擋下 | 太暗+太模糊 |
| vignette_fooler_moon | 擋下 | 太暗（整體平均被壓低，非直接靠形狀擋下） |
| **vignette_fooler_disc** | **⚠️ 放行（漏放）** | 灰白圓盤+黑邊，成功騙過形狀偵測，被模型分類為 Abnormal 73.4% |

## 已知限制（不是 bug，是這個方法本身的天花板）

1. **形狀偵測只看「四角暗、中心亮」，不理解語意**：只要準備一張黑邊+任何較亮圓形內容的圖，就能通過。
   `vignette_fooler_disc.png` 就是刻意做出來驗證這件事，確實漏放了。
   要徹底解決，需要訓練專門的「是否為耳鏡照片」分類器，或至少加入 Hough Circle 之類的形狀嚴謹度檢查。
2. **信心值不可靠**：漏放的那張圖信心值只有 73.4%，明顯低於真實照片的 98-100%，但目前沒有把
   「信心值中等」當成額外防呆條件（因為棋盤格測試也曾出現 70-99% 不等，此訊號本身不夠穩定，見下方）。
3. **Android 端 vs Python 校準腳本的微小差異**：兩邊的圖片縮放演算法（Skia vs PIL）不完全一致，對真實照片
   幾乎沒差別（9 張全部一致），但對高頻/人工合成圖片（如棋盤格）可能讓分類信心值有明顯差異。品質檢查
   的布林通過/擋下判斷本身對此不敏感（因為看的是區塊平均值，不是逐像素特徵），但無法保證 100% 一致。

## 原始模型 → TFLite → App 一致性

用同一個 `best_float16.tflite` 檔案，分別在 Python（`ai_edge_litert`）與 Android App 上跑同一批
真實照片，**9/9 結果與信心值完全一致**（前一輪對話已驗證，見 commit 歷史）。ONNX（float32）與
TFLite（float16）在真實照片上的輸出也一致，量化沒有造成可觀察的精度損失。

## 下一步建議（等使用者決定優先順序）

1. 收集更多真實負樣本（非耳膜照片）以及邊界案例，重新統計四個門檻的分布，調整成更嚴謹的數字
2. 若要徹底解決「形狀偽裝」問題，評估訓練專門的耳鏡照片分類器，或加入 Hough Circle 形狀檢查
3. 累積 `Log.d("EardrumClassifier", ...)` 記錄的真實信心值分布後，評估模型 calibration
   （如 temperature scaling），屆時再決定要不要把百分比呈現給使用者
